# 4. Microsoft Entra ID (Azure AD)

:contentReference[oaicite:2]{index=2}

---

# Previous Naming

| Old Name | New Name |
|---|---|
| Azure Active Directory | Microsoft Entra ID |

---

# Responsibilities

- User Authentication
- Access Control
- Identity Governance
- Security Policy Management
- Role Assignment
- Token Generation

---

# Real-World Analogy

```text

```

Every user must first pass identity verification before entering the cloud environment.

# 5. Authentication vs Authorization

These are the two most important security concepts in cloud engineering.

---

# 5.1 Authentication

Authentication verifies user identity.

---

## Core Question

```text
Who are you?
```

---

## Examples

- Username & Password
- Multi-Factor Authentication (MFA)
- OTP Verification
- Single Sign-On (SSO)

---

# Authentication Workflow

```text
User Login
      ↓
Identity Verification
      ↓
Authentication Successful
```

---

# 5.2 Authorization

Authorization determines what an authenticated user can access.

---

## Core Question

```text
What are you allowed to do?
```

---

## Example Roles

| Role | Access |
|---|---|
| Reader | Read-only |
| Contributor | Modify resources |
| Owner | Full administrative access |

---

# 6. Token-Based Authentication

Modern cloud platforms use token-based authentication systems.

---

# Authentication Flow

```text
User Login
      ↓
Entra ID Validates Credentials
      ↓
Token Generated
      ↓
Access Granted
```

---

# What is a Token?

A token is a temporary digital credential containing:
- User identity
- Session information
- Permissions

---

# Advantages

| Advantage | Description |
|---|---|
| Security | Password not repeatedly exposed |
| Scalability | Enterprise-ready authentication |
| Speed | Faster session validation |

# 14. Role-Based Access Control (RBAC)

RBAC is Azure’s authorization model.

---

# RBAC Workflow

```text
User
   ↓
Role Assignment
   ↓
Scope Validation
   ↓
Resource Access
```

---

# Common Roles

| Role | Permission |
|---|---|
| Reader | Read-only access |
| Contributor | Modify resources |
| Owner | Full control |

---

# Why RBAC is Important

- Centralized access management
- Enterprise-grade security
- Least privilege enforcement

---

# 15. Scope-Based Access Control

Permissions in Azure are always assigned within a scope.

---

# Types of Scope

| Scope | Access Range |
|---|---|
| Management Group | Multiple subscriptions |
| Subscription | Entire subscription |
| Resource Group | Specific project |
| Resource | Single resource |

---

# Example

```text
Babli → Contributor → babli-rg
```

User only receives access within the assigned scope.

---

# 16. Azure Roles vs Entra Roles

One of the most important enterprise IAM concepts.

---

# Entra Roles

Used for identity management.

---

## Examples

| Role | Responsibility |
|---|---|
| Global Administrator | Full identity control |
| User Administrator | Manage users |
| Privileged Role Administrator | Manage privileged access |

---

# Azure Roles

Used for Azure resource management.

---

## Examples

| Role | Responsibility |
|---|---|
| Owner | Full resource control |
| Contributor | Modify resources |
| Reader | View resources |

---

# Key Difference

| Entra Roles | Azure Roles |
|---|---|
| Identity Management | Resource Management |
| IAM Scope | Infrastructure Scope |

---

# 17. Global Administrator vs Subscription Owner

These are completely different administrative roles.

---

# Global Administrator

Controls:
- Entra ID
- Users
- Identity policies
- Authentication

---

# Subscription Owner

Controls:
- Azure resources
- Networking
- Storage
- Infrastructure

---

# Important Interview Point

```text
Global Administrator does NOT automatically become Subscription Owner.
```

---

# 18. Group-Based RBAC

Enterprise environments use Group-Based RBAC instead of assigning permissions individually.

---

# Workflow

```text
Create Security Group
       ↓
Add Users to Group
       ↓
Assign Role to Group
```

---

# Example

```text
rg-dev-contributors
```

All users inside the group inherit the assigned permissions.

---

# Advantages

| Advantage | Benefit |
|---|---|
| Scalability | Easier management |
| Security | Controlled access |
| Governance | Centralized permission model |

---

# 19. Minimum Privilege Principle

One of the most important cloud security principles.

---

# Core Rule

```text
Give only the minimum required access.
```

---

# Example

| User Type | Recommended Role |
|---|---|
| Intern | Reader |
| DevOps Engineer | Contributor |
| Senior Architect | Owner |

---

# Purpose

- Reduce attack surface
- Prevent accidental changes
- Improve security posture

# 24. Monolithic vs Microservices Architecture

---

# Monolithic Architecture

Entire application deployed as a single unit.

---

## Characteristics

- Simpler initial development
- Tightly coupled services
- Single deployment pipeline

---

# Microservices Architecture

Application split into independent services.

---

## Examples

- Authentication Service
- Payment Service
- Notification Service

---

## Advantages

- Independent scaling
- Faster deployments
- Better modularity
